# Полная База Знаний (FAQ) по проекту Dead Drop
Этот документ содержит полный список вопросов и ответов, возникших в процессе создания и обсуждения C++ сервиса.

## 1. Сборка и Настройка (CMake)
- В: Какие изменения нужны в CMakeLists.txt
О: Для проекта нужны:
```
Настройка стандарта C++20.
Подключение библиотек Crow (веб-фреймворк) и nlohmann/json.
Настройка сборки исполняемого файла (add_executable) и линковки (target_link_libraries).
```

- В: Я хочу, чтобы зависимости были через CPMAddPackage и в папке contrib.
О: Мы настроили CPM (менеджер пакетов).
```
 Он скачивает исходники библиотек (Crow, asio, json) в папку contrib внутри проекта, что позволяет держать зависимости локально и не засорять систему.
```


- В: В логе сборки есть ошибки и предупреждения (CPM deprecated, _method warning). Что они значат?
О: Это не ошибки, а предупреждения:
```
FetchContent_Populate is deprecated: Техническое сообщение CMake о том, что CPM использует старую функцию. На сборку не влияет.
identifier '_method' preceded by whitespace: Компилятор Clang жалуется на стиль кода внутри библиотеки Crow. Это тоже безопасно игнорировать.
```

- В чем смысл строки target_include_directories(... asio ...)?
О: Библиотека asio (нужна для Crow) является "header-only" (только заголовки). 
```
CPM скачивает её в нестандартное место в contrib. Эта команда говорит компилятору: "Ищи файлы .hpp также вот в этой папке", чтобы #include <asio.hpp> работал.
```


## 2. Запуск и Использование
- В: Я запустил приложение, как с ним взаимодействовать?
О: Откройте браузер по адресу http://localhost:8080.
```
Введите текст и нажмите кнопку — получите ссылку.
Откройте ссылку — увидите текст (он сразу удалится).
Обновите страницу — увидите 404.
```

- При запуске вижу "Internal Server Error: Template not found".
О: Программа ищет папку templates рядом с исполняемым файлом. При сборке через CMake бинарник лежит в build/, а шаблоны в корне.
```
Решение: Мы добавили в CMake команду copy_directory, которая сама копирует шаблоны в папку build при каждой сборке.
```

## 3. Архитектура и Логика C++
- В: Расскажи подробно, как работает программа (архитектура).
О:
```
- Клиент-Сервер: Браузер (Client) <-> C++ приложение (Server).
- Хранилище: SecretManager хранит данные в оперативной памяти (std::unordered_map).
- Потокобезопасность: Используется std::mutex, так как веб-сервер может обрабатывать много запросов одновременно.
```

- В: Как создается секрет? Из длинной строки получается короткая?
О: Мы не сжимаем строку. Мы выдаем ей номерок (как в гардеробе).
```
Длинный текст кладется в память (сейф).
Генерируется случайный ID (ключ от сейфа, 8 символов).
Пользователю отдается только ID.
```

- В: Что такое std::mt19937 rng_? Будет ли номер одинаковым при перезапуске?
О: Это генератор случайных чисел.
```
Нет, номера не будут повторяться.
Мы инициализируем его через std::random_device, который берет случайность из "шума" железа. Каждый запуск — новая случайная последовательность.
```

## 4. Взаимодействие Frontend (JS) и Backend (C++)
- В: Как C++ и JS взаимодействуют? Что такое GET и POST?
О: Аналогия с рестораном:
```
GET ("Дай меню"): Вы просите сервер показать страницу или данные. Ссылка в браузере — это всегда GET.
POST ("Вот заказ, готовь"): Вы отправляете данные (текст секрета) на сервер для обработки.
```

- В: Как JS понимает, что нужно обращаться к локальному серверу?
О: 
```
Через относительные пути. В коде мы пишем /api/secret (без домена). Браузер сам подставляет текущий адрес (http://localhost:8080).
```

- В: Отправляется пакет HTTP, а внутри JSON?
О: Да.
```
HTTP — это конверт (адрес, заголовки).
JSON — это письмо внутри (данные в формате { "key": "value" }).
JS упаковывает данные (JSON.stringify), C++ распаковывает (crow::json::load).
```


- В: C++ код возвращает ответ (return crow::response). Он сам понимает, куда отправить?
О: Да.
```
 HTTP работает поверх соединения (сокета) - TCP/IP. Клиент "висит на трубке", пока ждет ответа. Функция отправляет данные именно в этот открытый канал связи.
 ```

- В: Работа просмотра секрета (/secret/<string>). Как меняется HTML?
О:
```
Браузер шлет GET запрос .../secret/ID.
Сервер (C++) ищет ID, достает текст и удаляет его из памяти.
Сервер читает файл secret.html, находит метку {{secret_content}} и заменяет её на текст секрета.
Сервер отправляет браузеру уже готовый, измененный HTML. Это называется Server-Side Rendering (SSR).
```


- В: Что такое `<a href="/">` в HTML?
О: 
```
Это ссылка на корень сайта. При клике браузер делает запрос GET /, и сервер возвращает главную страницу (
index.html).
```
